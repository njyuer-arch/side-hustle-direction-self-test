## V2.0｜2026-10-09（短访谈与机会发现）

识别句：SHDST-20261009-V200。因真实使用反馈“问题多、答不上、报告增量少”，进行结构改版：原30个主线题变为后台线索库，不再逐题覆盖和显示30题进度；优先深问真实收款、本人角色、停止原因和当下个人交易入口。约8—12问争取第一版，但不设硬性题数。简单事实题给短选项及其他/不知道/跳过；整条消息只问一个点。约五六条有效回答时反馈一句观察。报告默认一屏，突出有据的新机会、最大风险及一项验证；证据不足允许阶段判断，不硬造新方向。仍保留三类入口、机会扫描、交易与风险核查、事实/推断区分及匿名反馈暂停。

当前为规则改版，已归档 V1.0.1 的 SKILL、目标总纲、README、入口和版本记录。依据现有三个使用样本设计，其中只有一份是独立从头访谈；尚未完成 V2.0 新用户或第三方平台效果验证，不能宣称完成率或商业效果提高。

## V0.10｜2026-10-09（目标重定位）

**使命：** 帮助用户不只判断已想到的项目，还要从本人经历、成果、兴趣、技能、可调用的人际资源及当前项目副产品中，发散发现可能没想到的挣钱机会；比较哪些可能更快见钱、哪些投入更低/能沉淀长期资产，并说明变现路径和未知。

- 将“发现本人未意识到的机会”设为最高优先级。访谈不只顺着用户的当前项目，必须主动扫描工作成果、兴趣偏好、亲友/朋友/老客户/同行的工厂、技能、渠道、客户，以及创业过程中产生的内容、案例、方法、工具和用户关系。
- 报告要展示用户原想法之外的机会假设，并解释机会如何从个人条件组合推出来、谁可能付钱、相对快收益/低边际成本/长期积累的优势。大胆发散，明确区分事实和推演；不能因未验证就删掉新方向，也不能把假设说成已验证结论。
- “自测”定位为机会发现与方向判断，不要求输出完整落地方案。所有后续提问、分析、报告和规则优化都回到本使命检查，不得只按单条新要求局部修补。
- V0.9.1 五份正式文件已完整保存至 archive 下 V0.9.1 快照；V0.5、V0.6、V0.8归档保持不变。匿名反馈继续暂停。本次规则更新尚未经过真实用户或第三方平台实测。

## V0.9｜2026-10-08（V0.10之前的历史版本记录）

状态：V0.8 原版与归档保持不变。V0.9保留公开 GitHub 项目的市场核查流程；匿名反馈功能目前暂停，不收集、不提交。

- 先核对 V0.9 标题与识别句 `SHDST-20261008-V09`；不匹配或无法读到完整规则即停止测试。
- 保留约30题固定主线、必要追问、时间与交易证据闸门、报告后继续修订及边际方向要求。
- 市场核查顺序为个人事实形成候选、核实需求与现有方案、核对个人交易入口、比较适配。
- V0.9 回归修正：对照用户给出的完整模拟，发现“30题答完”被当成完成访谈，且“未知也可报告”弱化了 V0.8 的关键事实追问门槛。现已恢复深访要求：答案含混、矛盾或影响方向排序的事实未问实，先逐题追问；报告分别比较能力、需求、付款证据、个人获客交付与现实条件。反馈已暂停，不征求提交授权。此次是规则修订，不代表豆包/GPT 已实测通过。
- V0.9 候选核查回归：两份 V0.6 桌面模拟都在30题后只做极少追问，直接把用户当前想法定为主方向；候选方向的市场核查也没有实际执行。根因是规则缺少“主线完成后、报告前”的候选核查环节。现已增加候选核查轮，按每个主要候选补查需求、现有解决、付款、个人获客交付及现实条件；涉及食品或专业服务时核实经营/资质边界。V0.5/V0.6 归档未改；本次仍是规则审查，不是第三方平台实测。
- V0.9.1 识别句更新：当前 V0.9 规则修订后识别句仍沿用 V0.9，旧版反馈询问因此未被版本核对识别。现将入口更新为 V0.9.1 / `SHDST-20261008-V091`，并同步入口页和使用说明。该版本强调报告前逐个核查候选；V0.5/V0.6 归档保持不变，匿名反馈继续暂停。
- V0.9.1 经营中项目核查补强：模拟水果团购案例暴露出报告直接建议淡季品，却未核实净利、复购口径、淡旺季、损耗和产能。现要求先问清经营账与退出条件，再比较互补品；无购买或供应证据时只列待核实，不直接点名商品。入口说明同步为 V0.9.1。
- 2026-10-08 本轮桌面情景模拟：短答无方向、健康方向且旧业务停过、专业岗位没有个人客户入口、报告后纠错与明确同意提交。发现报告闸门可能被误读成必须拿到正面市场证据，且若干固定题含多项；现已明确“问过但未知也可报告”，并将相关追问拆开。模拟是规则与内容走查，不等于豆包/GPT平台实测。
